# Ревью и фактические проверки

Дата: 14 октября 2026 года. Проверки выполнял Codex автоматически в Windows.
Python 3.12.10, SQLite 3.49.1. Существующего Git-репозитория не было;
коммиты задним числом не создавались.

## Этапы и реальные изменения

1. Визуально прочитаны все три страницы PDF. Проверены формат ответа платежа,
   пять обязательных сценариев, условия бонусов и критерии оценки.
   Рабочая папка содержала только пустые `work` и `outputs`.
2. Созданы модули FastAPI, модели, целочисленные расчёты и миграция.
   Идемпотентность с самого начала опиралась на UNIQUE и адресный ON CONFLICT,
   переход статуса — на условный UPDATE. Эти решения не выдаются за поздние исправления.
3. Первый pytest не собрал тесты: Starlette 1.8.0 предупредила об устаревшем
   httpx TestClient. После закрепления Starlette 0.52.1 обнаружилось второе
   предупреждение совместимости с AnyIO 4.15.1; закреплён AnyIO 4.11.0.
   Предупреждения не отключались: в pytest остаётся `filterwarnings = ["error"]`.
   Ruff нашёл 12 длинных строк, исправленных форматированием.
4. Первая рабочая серия: **142 passed in 9.05s**.
5. Ревью обнаружило зависимость конкурентной вставки от режима sqlite3.
   Добавлен режим с явными BEGIN и транзакционными SELECT. Он воспроизвёл
   **1 failed, 3 passed**, `sqlite3.OperationalError: database is locked`.
   Чтение цены завершено до транзакции INSERT. После исправления целевая
   серия дала **4 passed in 0.77s**, включая оба режима транзакций.
6. Добавлены осмысленные проверки отказа вставки/rollback/повторного использования
   ключа и округления 105 копеек через HTTP. Уточнены типы HTTP-обработчиков;
   после конфликта используется `.one()`, явно проверяющий наличие единственной
   сохранённой записи. Исключения БД не маскируются.
7. Создано второе, чистое виртуальное окружение. Установка выполнена только
   по готовому `requirements-dev.txt`, затем запущены полные проверки и сервер.

Пересмотренные решения: совместимые версии тестового стека; границы
транзакции создания; расширение проверок со штатного режима sqlite3 на
транзакционные чтения и сбой БД. Неподтверждённых ошибок и ручного ревью
человеком в этой истории нет.

## Живой HTTP-запуск

В отдельной временной БД проверены `/tariffs`, `/docs`, `/openapi.json`, создание,
чтение, список с фильтрами и вебхуки. Восемь одновременных запросов получили
`[200, 200, 200, 200, 200, 200, 200, 201]`, одинаковый платёж и одну запись.
Для standard / 3 месяца получен график `[663334, 663333, 663333]`.
Запрещённый переход вернул точный 409, отсутствующий платёж — 404.
После остановки и повторного запуска сохранились ID, суммы, статус и тарифы.
На повторном запуске включена подпись: запрос без неё дал 401, правильный
HMAC позволил выполнить succeeded → refunded.

Сначала HTTP-проверки прошли, но проверочный скрипт завершился с ошибкой
очистки временного файла: Windows-launcher Python оставлял дочерний процесс.
Исправлена остановка дерева только собственных процессов. Sandbox запрещал
taskkill, поэтому финальный повтор выполнен с разрешённым расширением прав
и завершился с кодом 0. Это проблема проверочного скрипта, не HTTP-сервиса.
Скрипт и логи находятся в рабочем каталоге вне сдаваемого репозитория.

## Проверка обязательных требований

| Требование | Реализация / доказательство |
| --- | --- |
| FastAPI, Python 3.11+, Pydantic v2, ORM, SQLite | requirements, понятные модули; локальная проверка 3.12 |
| Три тарифа в копейках без дубликатов | UNIQUE title, начальная вставка ON CONFLICT, тест перезапуска |
| Точные суммы, KVITTO10 в любом регистре | money.py; все тарифы/методы/варианты регистра, округление на границах |
| Неизвестный промокод → 422 | Pydantic field validator, тест отсутствия записи |
| card / sbp / installment; сроки 3/6/12 | enum, model validator, CHECK в БД, негативные тесты |
| Остаток в первые платежи, сумма графика точна | divmod; пример PDF, 0–150 копеек и большие суммы |
| Точный контракт четырёх маршрутов | response models; тесты кодов, всех полей, null и UTC |
| Идемпотентность не ограничена SELECT | UNIQUE, адресный INSERT ON CONFLICT, принудительная гонка |

| Только три разрешённых перехода | условный UPDATE, все 16 пар статусов и конкурентные вебхуки |
| Отсутствующий платёж → 404 | GET и webhook проверены |
| Commit, rollback, закрытие сессий | контекстные менеджеры, проверка отказа вставки и восстановления |
| Постоянное хранение | файловая БД, тест и живой перезапуск |
| Пять обязательных сценариев pytest | покрыты с проверкой значений и БД; всего 145 тестов |
| README и AI_LOG | установка, curl, допущения, честная история одного запроса |

Реализованы все шесть бонусов: Docker/Compose, HMAC, Alembic, список платежей
с фильтрами, Actions и AGENTS.md. Доступность конфигурации не равна фактически
проверенному запуску Docker или CI; эти ограничения перечислены выше.

## Ограничения и оценка

Один worker и файловая SQLite подходят для локальной проверки. При долгой
блокировке возможен HTTP 500; бесконечных повторов и обещания любой нагрузки
нет. Миграции при старте не защищены от одновременного первого запуска
нескольких процессов. Список платежей пока без пагинации. Без секрета HMAC
намеренно отключён. Защита от replay и банковская интеграция вне задания.

Каждому критерию PDF соответствует реализация и проверка, а исходники небольшие
и объяснимые Junior-разработчику. Самые сложные места для защиты — UNIQUE при
гонке, условный UPDATE, разделение SQLite-транзакций и подпись исходных байтов.
Баллы и решение работодателя не гарантируются; понимание кода должен лично
подтвердить кандидат на созвоне.
