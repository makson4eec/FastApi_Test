# Использование ИИ

Использован Codex в настольном приложении, семейство модели GPT-6. Точный
идентификатор варианта модели не отображался. Другие агенты и модели не
привлекались. Исходники, тесты и документация созданы ассистентом с нуля по
трём страницам PDF и одному подробному запросу пользователя. Старые проекты
и готовые реализации не использовались. Для проверки поведения библиотек
ассистент обращался к официальной документации SQLAlchemy и FastAPI.

Фактически использован **один ключевой пользовательский запрос**. В сокращении:
«Самостоятельно реализовать API платежей на FastAPI по всем трём страницам PDF;
обеспечить точные копейки, идемпотентность с UNIQUE, статусы, тесты; провести
ревью, исправить реальные проблемы и фактически запустить проверки».
Отдельных запросов пользователя на последующий ревью не было; следующие
этапы ассистент выполнил в рамках этого запроса.

Предложены целочисленное округление скидки, `divmod` для графика, уникальный
ключ с адресным `ON CONFLICT`, условный UPDATE статуса и Alembic как единый
источник схемы. Эти решения проверялись тестами значений и состояния БД.
На первом запуске новые Starlette / AnyIO остановили сбор тестов из-за
предупреждений несовместимости с httpx. Закреплены совместимые версии;
строгая проверка предупреждений осталась включённой. Ruff выявил длинные
строки в тестах, исправленные форматированием.

После первых 142 успешных тестов ревью выявило риск повышения SQLite-снимка
чтения до записи. Дополнительный тест с транзакционным SELECT действительно
упал с `database is locked`. Чтение тарифа отделено от короткой транзакции
вставки; тест прошёл в обоих режимах. Добавлены проверки rollback при отказе
вставки и округления 105 копеек через API.
Итоговые результаты и ограничения среды записаны в `REVIEW.md`.
