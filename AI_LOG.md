# Использование ИИ

Использован Codex в настольном приложении, семейство модели GPT-6. Точный
идентификатор варианта модели не отображался. При первоначальном создании
другие агенты не привлекались. Исходники, тесты и документация созданы с нуля по
трём страницам PDF и одному подробному запросу пользователя. Старые проекты
и готовые реализации не использовались. Для проверки поведения библиотек
ассистент обращался к официальной документации SQLAlchemy и FastAPI.

При первоначальном создании использован **один ключевой запрос**. В сокращении:
«Самостоятельно реализовать API платежей на FastAPI по всем трём страницам PDF;
обеспечить точные копейки, идемпотентность с UNIQUE, статусы, тесты; провести
ревью, исправить реальные проблемы и фактически запустить проверки».
Этапы первоначального ревью ассистент выполнил в рамках этого запроса.
Позднее пользователь спросил «как его запустить в вс коде дай пошаговую
инструкцию», затем прислал ошибки pytest и спросил «у человека который
возьмёт мой код из гита будет также ошибок?».

Предложены целочисленное округление скидки, `divmod` для графика, уникальный
ключ с адресным `ON CONFLICT`, условный UPDATE статуса и Alembic как единый
источник схемы. Эти решения проверялись тестами значений и состояния БД.
На первом запуске новые Starlette / AnyIO остановили сбор тестов из-за
предупреждений несовместимости с httpx. Закреплены совместимые версии;
строгая проверка предупреждений осталась включённой. Ruff выявил длинные
строки в тестах, исправленные форматированием.

После первых 142 успешных тестов ревью выявило риск повышения SQLite-снимка
чтения до записи. Дополнительный тест с транзакционным SELECT действительно
упал с `database is locked`. Чтение тарифа отделено от короткой транзакции
вставки; тест прошёл в обоих режимах. Добавлены проверки rollback при отказе
вставки и округления 105 копеек через API. Автоматические проверки и живой
HTTP-запуск выполняет ассистент; ручные действия разработчика не заявляются.
Итоговые результаты и ограничения среды записаны в `REVIEW.md`.

15 октября пользовательский запуск показал 16 passed / 129 errors из-за
прав Windows на `pytest-of-se191`: каталог принадлежал sandbox-учётной записи
Codex. Повторная проверка также выявила конфликт доступа к `.pytest_cache`.
Добавлен новый временный каталог на каждый запуск с автоматической очисткой,
общий кеш отключён. Один дополнительный агент прочитал установленный код
pytest и проверил порядок хуков и очистку. Итог: 145 passed в sandbox и
145 passed вне него, Ruff без ошибок. Коммиты и отправка в GitHub не выполнялись.

Для собственного дополнительного ревью можно действительно задать:
«Почему разделение транзакций не ослабляет UNIQUE и что меняется в PostgreSQL?»
и «Покажи минимальную доработку для нового срока рассрочки и нужные тесты».
Это предложения будущих запросов, а не выполненные обращения.
